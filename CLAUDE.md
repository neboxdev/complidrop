# CompliDrop — Claude Code project guide

CompliDrop is a $49/mo SMB compliance-document SaaS: upload a COI / license / permit → automatic extraction → rules evaluation → vendor portal → reminders → audit-ready export.

Canonical tech reference: `C:\NewStart\Company documents\complidrop-technical-architecture.md` (that path is the only current copy — do not trust repo-local snapshots). Read it before architectural changes, and keep it in sync when a decision diverges from it. Phase-2 scope lives beside it in `complidrop-phase2-architecture.md` — do not build Phase 2 features until the product hits $5K MRR.

**Keep this file lean — it loads into every session.** It is the map: hard rules, a one-to-three-line invariant index, pointers. The detail lives on demand in:

- `docs/adr/` — rationale + amendments per decision ([catalog](docs/adr/README.md)). **Read the linked ADR before touching an indexed area.**
- [.claude/reviewers.md](.claude/reviewers.md) — review-time facts: rosters, the do-NOT-flag trap list, sensitive areas + `careful-review` globs, commit scopes, scale, severity anchors.
- [frontend/CLAUDE.md](frontend/CLAUDE.md) — frontend conventions (auto-loads for work under `frontend/`).
- [docs/dev-environment.md](docs/dev-environment.md) — dev isolation, boot banner, full secrets/env-var reference.

When a change alters an invariant: update the ADR (or add one), sync the one-line index entry here, and sync reviewers.md in the same PR.

## Stack

- **Backend**: ASP.NET Core (.NET 10) Minimal APIs at `api/CompliDrop.Api`. EF Core 10 + Npgsql against Neon Postgres. DB doubles as durable extraction queue and audit sink.
- **Frontend**: Next.js 16 + React 19 + Tailwind 4 + shadcn/ui at `frontend/`. App Router, TanStack Query, React Hook Form + Zod, sonner toasts.
- **Solution**: `api/CompliDrop.slnx` wraps `CompliDrop.Api` + `CompliDrop.Api.Tests`.
- **Deploy**: Railway auto-deploys `main` — merge = prod deploy; EF migrations auto-apply at startup before serving traffic (fail-fast, boot-time drift guard — [ADR 0016](docs/adr/0016-apply-ef-migrations-on-startup.md)).

## Hard rules

- Never expose API keys in code — config + user-secrets only. Never commit the contents of `connection string.txt`.
- Never create migrations without reading spec §3 first.
- **Tenant isolation**: `AppDbContext.CurrentOrgId` drives global query filters on every tenant entity. `IgnoreQueryFilters()` / `SystemDbContext` only inside background workers or system contexts — in request-path code it is tenant leakage, a blocker.
- Vendor portal endpoints (`/api/portal/*`) are PUBLIC — treat all input as untrusted.
- File validation uses magic bytes (PDF / JPEG / PNG), never `Content-Type`; 10 MB cap at Kestrel.
- Webhook handlers verify signatures and dedupe event ids (Stripe → `ProcessedStripeEvent`; Resend → Svix `Resend:WebhookSecret`).
- Raw SQL touching a `timestamptz` column uses bare `now()` / `DateTime.UtcNow`, never `AT TIME ZONE` whose result feeds back into a timestamptz comparison or assignment ([ADR 0009](docs/adr/0009-no-at-time-zone-on-timestamptz-in-raw-sql.md); output-only conversion for display stays legitimate).
- Three staged feature flags stay default-OFF pending the [G1-COUNSEL-BRIEF](docs/rule-engine/G1-COUNSEL-BRIEF.md) §0 attorney/broker sign-off: `RuleEngine:Enabled`, `TemplateCorrections:Enabled`, `ComplianceClaims:CorrectedAdditionalInsuredWording`. Never flip, soften, or unify them; the flag-OFF legacy copy/templates are deliberate merge-safety no-ops, not bugs, and the staged corrected variants are not dead code ([ADR 0036](docs/adr/0036-system-template-seed-convergence.md), [ADR 0043](docs/adr/0043-additional-insured-claim-wording-staged-behind-flag.md)).
- Dev stays isolated from prod: Neon `dev` branch, Azurite, no `Resend:ApiKey` (email-silent), `sk_test_` Stripe. The boot banner names the resolved targets — see [docs/dev-environment.md](docs/dev-environment.md) (#271).

## Domain invariants — read the ADR before touching the area

- **Auth**: httpOnly cookie JWT (`cd_session` 15 min, `cd_refresh` 30 days path `/api/auth`), BCrypt work factor 12, lockout after 10 failed attempts with exponential backoff. Tokens never leave the server; the frontend just sends `credentials: "include"`. Per-request principal revalidation: [ADR 0014](docs/adr/0014-per-request-principal-revalidation-and-security-stamp.md).
- **Audit log** ([ADR 0044](docs/adr/0044-audit-client-input-clamped-at-the-boundary.md), #372): `AuditSaveChangesInterceptor` auto-sets `UpdatedAt`, turns deletes into soft deletes, and emits `AuditLog` rows with Before/After JSON on every entity mutation; non-entity events go through `IAuditLogger`. Client-controlled strings reaching bounded audit columns are clamped at the ONE `ICurrentUser` boundary; an unusable inbound `X-Trace-Id` is REPLACED (charset `[A-Za-z0-9_-]`), never truncated, so client free text can't reach the un-redacted Sentry `correlation_id` tag.
- **Request input length guards** ([ADR 0046](docs/adr/0046-request-input-length-guards.md), #389): every request string bound for a `varchar(n)` is guarded before `SaveChanges` (Npgsql does not truncate — unguarded means 22001 → 500 where a 400 belongs). `Services/InputLengths.cs` owns the widths (consumed by `ModelConfiguration`, pinned by test); `Endpoints/InputLength.FirstViolation` is the one rejection envelope (`validation.too_long`; the older `validation.contact_email` / `validation.email` stay separate on purpose). Reject vs clamp is PER-FIELD and the axis is who authored the value: user-TYPED content rejects, machine-chosen incidentals clamp (`ColumnClamp.To`), `documentType` coerces on the two ingress paths. The `Idempotency-Key` clamp sits at the single point the header is read (lookup and storage see the same string; the public portal IGNORES an oversize key instead). Upload blob cleanup goes through `Endpoints/OrphanBlobCleanup` — confirms document ABSENCE before deleting, on its own 10s token (never the request `ct`, never `None`). Any index name a 23505 catch matches on is ONE `Services/` constant; a JSON-null positional record parameter needs its own blank guard beside the length check.
- **Idempotency** ([ADR 0029](docs/adr/0029-idempotency-co-commit-reservation.md), [ADR 0032](docs/adr/0032-portal-upload-idempotency.md), #336/#333): mutating POSTs accept `Idempotency-Key`; the dedupe record co-commits in the SAME transaction as the side effect, so of two in-flight same-key requests exactly one wins and the loser replays the winner's exact response (never a 409). A committed record replays for as long as the row exists — `ExpiresAt` is a GC hint, not a replay filter. The portal upload key is scoped `portal:{token}:{key}` and the loser's upload permit rolls back with its transaction.
- **Extraction pipeline** ([ADR 0045](docs/adr/0045-canonical-document-type-vocabulary.md), #373; tech doc §5): always-on Document AI OCR → configurable LLM (`Extraction:Provider`, Gemini Flash default; provider-agnostic prompt; `ExtractionPromptVersion` recorded per document). `ExtractionWorker` polls every 5s with `FOR UPDATE SKIP LOCKED` + 5-minute zombie reclaim and claims on `ExtractionStatus == Pending` — never write `Pending`/`Processing`/`Failed` from request code. `documentType` is ONE shared vocabulary (`Services/CanonicalDocumentTypes.cs`, compared ordinally by rules + supersession): the worker COERCES the model's answer through it (blank/absent keeps the stored type; a positive `"other"` overwrites), while `UpsertRule` and the PATCH edit REJECT non-canonical types. Model-response columns are guarded per ADR 0045 §4 (sub-type dropped when over-length, field values truncated display-only — the jsonb keeps the full value), and a clipped field value is DISCLOSED ([ADR 0049](docs/adr/0049-clipped-extraction-field-is-disclosed-not-silent.md), #444): `DocumentFieldDto.FieldValueTruncated` is derived at read time by `Services/DocumentFieldTruncation` reproducing `ColumnClamp.To` against the jsonb copy — never re-derived client-side, never persisted (it self-clears once a save makes the two copies agree). Never-graded is NOT fail-safe — closed by #443 / ADR 0048 (see the index entry below); legacy non-canonical rows are still deliberately NOT laundered (a destructive data operation needing human sign-off), they just now read `Pending` everywhere instead of rolling up to Covered.
- **Re-extract in-flight guard** ([ADR 0050](docs/adr/0050-reextract-refuses-a-live-extraction-claim.md), #365): `POST /documents/{id}/reextract` re-arms the queue with ONE conditional `ExecuteUpdateAsync` (never a read-then-write — that guard would race the very claim it checks) and refuses a claim the WORKER still believes in, `409 document.extraction_in_progress`, writing nothing. The window is `ExtractionWorker.ZombieClaimTimeout` — ONE constant that `ClaimSql` is now BUILT from, so the endpoint and the claim can't drift; a stale claim and a `Processing` row with no start time both pass through (the worker would reclaim them anyway / could never reclaim them at all). Deliberately NOT a `Document` concurrency token (#366 shipped without one — see Verdict atomicity above) and deliberately NO `(DocumentId, FieldName)` unique index — duplicates are reachable on plain single-worker paths, so it needs a measured population + signed-off dedupe (ADR 0050 Options D/E). The 409 is only reachable from a tab that believes the read FINISHED (`isProcessing` derives from the last payload), so the detail page's `reextract.onError` invalidates the document query on that ONE code — otherwise "still reading" toasts over a `Read` badge and every further click 409s until a manual reload (Amendment 1); a blanket invalidate-on-any-error is the bug, not the fix.
- **Extraction trust & verdict overlays** ([ADR 0040](docs/adr/0040-unreadable-canonical-value-fails-closed.md), [ADR 0041](docs/adr/0041-future-effective-not-yet-in-force-reads-pending.md), [ADR 0042](docs/adr/0042-distrusted-extraction-per-field-gate-and-coverage-exclusion.md), #383/#362/#401): an UNREADABLE canonical value (non-blank, won't parse) fails CLOSED everywhere — every rule operator fails it, the raw-string fallback resolves only values that re-parse, and the document degrades to `ManualRequired`; `Services/DocumentFieldReadability` is the one predicate and `DocumentEndpoints.ResolveManualReview` the one request-side resolver (computed from RESULTING state, never from submitted field names). A future-effective cert reads `Pending` on every read surface while the STORED verdict stays real so it self-heals on the crossing date. A `ManualRequired` doc — and, per Amendment 2 (#365), a terminally `Failed` one NOBODY CONFIRMED (`!IsManuallyVerified`), since a re-arm overwrites `ManualRequired` and nothing restores it — is excluded from vendor in-force coverage (read-time only; each exclusion keeps a human exit, `Pending`/`Processing` deliberately NOT excluded, document-level counts/badges deliberately untouched). Per-field confidence gate: ANY present verdict-bearing field (`Services/VerdictBearingFields.cs`) below the shared 0.7 threshold routes to `ManualRequired` even if the average clears it.
- **Never-graded documents** ([ADR 0048](docs/adr/0048-never-graded-document-asserts-no-affirmative-verdict.md), #443): a doc with ZERO `ComplianceCheck` rows was never graded and asserts no affirmative verdict — `Services/DocumentGrading.IsGraded` is the one recognizer, `ComplianceStatusDeriver.Effective`'s REQUIRED `isGraded` the one decision, and an affirmative overlaid verdict reads `Pending` (Expired/NonCompliant never demote). READ-ONLY like ADR 0041 — the stored verdict stays real so it self-heals when something grades it. Mirrored on EVERY surface including the document-level ones (ADR 0042's carve-out does not transfer: no second badge says "nothing graded this"); the vendor rollup inherits it through the deriver. The export also discloses the count (`RequirementsChecked` column / "(no requirements checked)"). A demoted doc must stay REACHABLE: the dashboard's `awaitingReview` tile and the `?status=Pending` list are one population by construction (`ComplianceStatusDeriver.ReadsPending`), and the `expiringSoon` tile is labelled by its STATUS, not a date range. The detail page's "Not checked yet" card may only name a cause it can KNOW: `DocumentDetail.vendorHasChecklist` + `vendorChecklistRuleCount` separate the four zero-check causes, only a SETTLED extraction gets a cause named at all, and a non-canonically-stored type leads with the type correction instead of a duplicate-adding CTA.
- **Verdict atomicity** ([ADR 0030](docs/adr/0030-compliance-verdict-combined-unit-of-work.md) + Amendment 1, #337/#366): the persisted `ComplianceStatus` must never contradict the inputs it was computed from — each input-writer folds `IComplianceCheckService.ApplyEvaluationAsync` into its OWN unit of work so (inputs, verdict) commit in ONE `SaveChanges`, making races last-writer-wins on the whole tuple, never a torn pair. A recompute failure degrades to `Pending`, never a confident verdict from stale inputs. Pure re-grades use `EvaluateAsync`. One transaction is not enough for the two PARTIAL writers (`UpdateFields`/`UpdateDocument` rebuild the whole `ExtractionFields` mirror from their own snapshot but write back only their own typed columns), so those two — and ONLY those two — run under `REPEATABLE READ` via `Endpoints/DocumentWriteConcurrency` and RE-RUN against a fresh read on Postgres `40001` (`Services/DocumentConcurrency`), bounded at 3 attempts, then `409 document.concurrent_update` having committed NOTHING. On those two the degrade-to-`Pending` rule is now CONDITIONAL: a DATABASE-level recompute failure aborts their transaction (`25P02`) and commits nothing instead. Deliberately NO `xmin` token and no schema change — an entity-level token makes EVERY `Document` write optimistic, worker persist included. Open residual: the worker READS but never WRITES `VendorId`, so a mid-extraction vendor PATCH still leaves the new vendor with the old vendor's verdict ([#460](https://github.com/neboxdev/complidrop/issues/460)).
- **Document supersession** ([ADR 0033](docs/adr/0033-document-supersession-expired-liability.md) + Amendments 1–2, #327/#362): a newer doc supersedes only if it also EXTENDS coverage (`ExpirationDate >=` the old doc's) AND is continuous (`EffectiveDate` null or `<=` the old expiry) — so a renewal can never make a genuinely-unmet expired liability vanish or paper over a live coverage gap. De-counts ONLY the Expired liability (dashboard count, expired pipeline bucket, `?status=Expired` list, reminder windows); the export annotates-but-keeps; deliberately NOT applied to compliant/nonCompliant/expiringSoon or future pipeline buckets.
- **Reminders** ([ADR 0025](docs/adr/0025-reminder-catch-up-window-and-failed-send-retry.md), [ADR 0031](docs/adr/0031-reminder-bounce-complaint-suppression.md), #340): hourly tick, per-org from local 08:00 with catch-up until local midnight, failed sends retry in place; deduped per recipient by the `(ReminderId, DocumentId, SendDate, RecipientEmail)` unique index; per-`(org, email)` suppression written by the Resend webhook (spam complaint always; only `Permanent` bounces) and surfaced on the vendor + activity feed. The sample demo never gets mail — the skip keys on the ADDRESS (`SampleData.IsUndeliverableSampleAddress`), never on `Vendor.IsSample`, because a repurposed sample vendor with a real address must keep receiving mail (#367 / ADR 0028 Amendment 1).
- **Sample demo** ([ADR 0028](docs/adr/0028-sample-demo-reuses-real-pipeline-and-shared-system-templates.md), #238): `POST`/`DELETE /api/sample` seeds/clears a generated sample COI run through the REAL pipeline plus a sample vendor on the system "Caterer" checklist. Occupies no paid plan slot on any limit-enforcing/reporting surface (shared `PlanDocumentScope.CountsTowardLimit`, pinned by test) though the dashboard's `totalDocuments` deliberately still counts it. One live sample per org (partial unique index); clear DELETES the blob — a normal document delete RETAINS its blob ([ADR 0013](docs/adr/0013-account-deletion-is-soft-delete-plus-pii-scrub.md)).
- **Vendor portal limits** (#242, #333): the UPLOAD route is rate-limited `portal-token` 10/hr + `portal-ip` 30/hr, plus per-link `MaxUploads` and a per-org monthly cost ceiling; the read routes are uncapped per-token (status polling) with a 240/hr per-IP backstop.
- **Vendor contact email** ([ADR 0038](docs/adr/0038-vendor-contact-email-mirrored-validation.md), #369): ONE strict rule mirrored across `Services/ContactEmail.cs` ↔ `frontend/src/lib/contact-email.ts`, agreement pinned by the shared corpus in the api test tree + a BMP-walking test each side. Deliberately STRICTER than the lax account-email check (`AuthEndpoints.IsValidEmail`) — a vendor address is never proven by a verification mail; do not unify them. Blank stays legal; edges stripped by linear scan (never regex), blank class spelled as explicit `\uXXXX` ranges (never `\s`).
- **Documents-list URL state** ([ADR 0039](docs/adr/0039-documents-url-source-of-truth-overlay.md), #370): filters derive from the URL only — `useSearchParams()` is base truth with the page's own writes overlaid as a queue until the router echoes them. `frontend/src/test/navigation.ts` models both History/router orderings deliberately; do not "simplify" either. Details in [frontend/CLAUDE.md](frontend/CLAUDE.md).
- **Frontend error monitoring** ([ADR 0037](docs/adr/0037-frontend-sentry-pii-scrubbing-and-gating.md), #356): Sentry is a no-op unless `NEXT_PUBLIC_SENTRY_DSN` is set AND `NODE_ENV=production`; a unit-tested scrubber strips cookies/tokens/emails/bodies. Application code must NEVER hand raw document field values or user content to `captureException`/`setExtra`/`setContext`. Backend correlation via the `correlation_id` tag.
- **Additional-insured claim wording** ([ADR 0043](docs/adr/0043-additional-insured-claim-wording-staged-behind-flag.md), #396): the corrected wording sits behind the CLM-1 flag (see Hard rules) and is COPY-ONLY — the flag never moves a pass/fail verdict (parity pinned by test). Distinct from `TemplateCorrections` on purpose (different sign-off).
- **Export disclaimer** ([ADR 0047](docs/adr/0047-exports-carry-a-non-advice-disclaimer.md), #402 / CLM-3): all three artifacts (audit PDF, vendor package, CSV) carry ONE shared `ExportService.Disclaimer` — ON by default, deliberately NOT flag-staged like ADR 0043 (a disclaimer is one-directional risk reduction; default-OFF would leave the bug live). The PDFs render it from `ApplyPageDefaults`' `page.Footer()` so it lands on EVERY page above the `CompliDrop · {org}` attribution; the CSV appends it as a TRAILING row (never a preamble — row 1 stays the header). Scope is the three reliance artifacts, NOT the account data export (a portability dump — recorded, not overlooked). Wording AND prominence are provisional pending the CLM-3 attorney pass.

## Workflow & record-keeping

Substantive changes flow through three record layers (typos and trivial fixes excepted):

1. **Tickets** — GitHub Issues (`docs/tickets/` only when `gh` is unavailable). Every non-trivial change starts with a ticket.
2. **Conventional Commits** — always reference the issue: `feat(extraction): retry on Gemini 5xx (#42)`. Scopes: see reviewers.md.
3. **ADRs** (`docs/adr/`) — append-only; supersede or amend via the ADR itself; keep the [catalog](docs/adr/README.md) updated.

Mechanics live in the machine-level claude-kit (`~/.claude/skills/`: plan, pm-review, breakdown, start, review, epic-review, ticket, tickets, adr) with this repo's overlay in [.claude/reviewers.md](.claude/reviewers.md). **A code change that alters a reviewers.md fact updates reviewers.md in the same PR.**

- **Autonomy contract** (`~/.claude/skills/start/SKILL.md`): sessions implement, review, and merge on their own via a deterministic gate; they stop only for the seven enumerated exceptions (destructive migrations/data deletion, careful clearance not obtained, secrets/prod config, force-push, unresolvable test failures, unfixable findings, genuine ticket ambiguity). `careful-review` tickets and Sensitive-glob PRs merge autonomously only after a **careful clearance**: two independent Fable-5 max-effort reviewers who must BOTH answer "safe to merge", recorded against the PR's current head SHA (`/start` Phase 6 step 4b — any later push invalidates it); only a PR they still won't clear after 3 fix rounds waits for a human. Founder decision 2026-07-28, superseding merged-by-a-human.
- **Review contract** (`~/.claude/skills/review/references/findings-contract.md`): every bug finding is adversarially verified by 3 independent Opus verifiers (reviewer agents pinned to Opus, never the premium session model); every CONFIRMED bug gets fixed regardless of severity; suggestions ≥99% implemented in the same PR — "listed in the PR body but not fixed" is not a valid outcome.
- Tests are mandatory after implementation: xUnit for pure logic, `WebApplicationFactory` integration tests at boundaries (Postgres, Blob, Document AI, Gemini, Stripe, Resend), Vitest on the frontend.
- Never silently diverge from a ticket's acceptance criteria — update the ticket first.

**Epics**: `bug`-labeled issues auto-index into the rolling epic [#48](https://github.com/neboxdev/complidrop/issues/48) (defects, latent fragilities, contract ambiguities — not features/refactors/test scaffolding; a deferred pure suggestion stays `task`; see [ADR 0006](docs/adr/0006-rolling-bug-fix-epic.md)). Others: #41 simplification (gated on launch), #150 post-launch follow-ups.
